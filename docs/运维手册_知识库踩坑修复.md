## 二、核心踩坑点 & 修复记录

### 坑1：pypdf 缺失 → 文档上传成功但向量化静默失败

**现象**：文档上传成功，但搜索永远找不到内容。

**原因**：异步向量化线程调用 `pypdf` 解析 PDF 时，依赖未安装，异常被吞没。

**修复**：
```bash
docker exec ai-test-backend pip install pypdf -i https://pypi.tuna.tsinghua.edu.cn/simple
docker compose restart backend
```

**之后必须删除旧文档并重新上传**，旧文档不会自动重试。

---

### 坑2：pymilvus 2.4 Hit 对象不是 dict

**现象**：Milvus 升级到 2.4 后，搜索永远返回空。

**原因**：`hit.get('entity')` 在 2.4 的 `Hit` 对象（NamedTuple）上直接报错。

**修复文件**：`backend/core/tools/milvus_store.py`

**修复代码**（`search` 方法中）：
```python
# 旧代码（不兼容 pymilvus 2.4）
for hit in res:
    entity = hit.get('entity', {})   # Hit 对象没有 .get()！
    score = float(hit.get('distance', 0))

# 新代码（兼容 dict 和 NamedTuple）
for hit in res:
    if isinstance(hit, dict):
        entity = hit.get('entity', {})
        distance = hit.get('distance', 0)
    else:
        entity = hit.entity if hasattr(hit, 'entity') else {}
        distance = hit.distance if hasattr(hit, 'distance') else 0
```

---

### 坑3：similarity_threshold=0.5 过滤太狠

**现象**：搜索返回5条，但问答接口返回"未找到相关信息"。

**原因**：embedding 模型对"概括性问题 vs 具体内容"的相似度只有 0.3~0.4，被 0.5 阈值全部过滤。

**修复文件**：`backend/knowledge_base/services.py`

**修复**：去掉 `answer_question` 和 `answer_question_stream` 中的 `similarity_threshold=0.5`：
```python
# 旧
hits = self.store.search(query_vector=query_vector, top_k=5, kb_id=knowledge_base_id, similarity_threshold=0.5)

# 新
hits = self.store.search(query_vector=query_vector, top_k=5, kb_id=knowledge_base_id)
```

### 坑4：前端 404 —— 路径拼写不一致

**现象**：前端上传文档 404。

**原因**：
- 前端请求：`/api/knowledge-base/3/upload_document/`
- 后端注册：`/api/knowledge/knowledge-bases/...`

**修复**：重新构建前端（`npm run build`）并部署。

## 六、面试踩坑话术

> "在做 RAG 知识库时踩过几个典型的工程坑：
> 1. 异步向量化缺少 `pypdf` 依赖，静默失败 → 必须有异常捕获 + 状态回写
> 2. `pymilvus` 2.3 → 2.4 升级后 `Hit` 从 dict 变成 NamedTuple → 需要 isinstance 兼容
> 3. `similarity_threshold=0.5` 对概括性问题过滤太狠 → 让 LLM 自己做相关性判断
> 4. 前后端 API 路径硬编码不一致 → 统一走配置管理"
