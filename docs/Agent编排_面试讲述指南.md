# Agent 编排 — 面试讲述指南

> 面试官不会问你代码细节，他们关心的是脑子里的那张图。
> 这份指南不涉及代码，只讲思路、流程、设计决策。

---

## 一、一句话讲清楚

> "我用了 LangGraph 的状态图模式来做多Agent编排。核心是：Plan（拆需求）→ Orchestrate（调度执行）→ Verify（验证回退），三个节点构成闭环。支持并行执行组、失败自愈和实时进度推送。"

---

## 二、核心流程（你能画在纸上讲）

```
用户输入
   │
   ▼
┌──────────┐
│ ① Plan   │  LLM把需求拆成执行计划（步骤列表）
└────┬─────┘
     │
     ▼
┌────────────────┐
│ ② Orchestrate  │  按并行组调度Agent执行
│                │  ┌─────────────────────┐
│  并行组 A      │  │ TestCaseGen  并发   │
│  并行组 B      │  │ DataFactory + Exec  │
│  并行组 C      │  │ Evaluator           │
│                │  └─────────────────────┘
└───────┬────────┘
        │
        ▼
┌──────────┐    验证失败
│③ Verify  │──────────────► 回 Plan 重试
└────┬─────┘
     │ 通过
     ▼
  最终输出
```

**讲述要点：**
- Plan 阶段：LLM 分析用户需求，输出一个有先后顺序的步骤列表，标注哪些步骤可以并行。
- Orchestrate 阶段：按并行组批量调度。同一组的步骤并发执行，组和组之间串行（保证依赖）。
- Verify 阶段：检查所有步骤结果是否完整、数据是否一致。失败就回退到 Plan 重新规划，最多重试2轮。

## 三、5个Agent怎么分工的

面试官通常会问："你有几个Agent？各做什么？"

| Agent | 一句话职责 |
|-------|-----------|
| **PlanAgent** | 读需求 → 拆步骤 → 分并行组，输出一个可执行的计划 |
| **TestCaseGeneratorAgent** | 根据需求 + 知识库生成测试用例 |
| **DataFactoryAgent** | 给用例准备测试数据，支持变量绑定 |
| **ExecutionEngineAgent** | 执行测试用例，收集结果和Allure报告 |
| **EvaluatorAgent** | 评估通过率、覆盖率，出评测报告 |

**讲述逻辑：** PlanAgent 是大脑，后面四个是手。大脑决定先做什么后做什么、谁能一起做；手各自干活。

## 四、面试官可能追问的设计决策

### Q1：为什么用 LangGraph，而不是简单的 if-else 调度？

> "if-else只能做线性流程。我的场景有三个需求是线性满足不了的：
> 1. 条件回退——验证失败要回到Plan重新规划，这是个环
> 2. 并行控制——不同步骤有依赖关系，有的能并发、有的必须等
> 3. 状态共享——所有Agent需要在同一个上下文里协同，中间结果要保留
>
> LangGraph的StateGraph天然支持有向图、条件边、共享状态，比手写调度逻辑可靠。"

### Q2：并行和串行是怎么决定的？

> "不是写死的，是PlanAgent自动分析的。LLM在拆需求时会给每个步骤打一个parallel_group标记：
> - 没有依赖的步骤 → 同组 → 并行
> - 有依赖的步骤 → 不同组 → 串行
>
> 比如：生成用例和准备数据可以并行（同组），但执行必须在生成之后（不同组）。"

### Q3：失败了怎么办？

> "三层保障：
> 1. 步骤级：单个Agent失败不影响同组其他Agent
> 2. 工作流级：Verify节点检测整体失败 → 条件边回退到Plan重新规划
> 3. 自愈引擎：根据错误类型匹配修复策略，比如知识库未命中就自动补充检索"

### Q4：怎么让前端看到实时进度？

> "SSE（Server-Sent Events）推送。工作流每执行一个节点或阶段变更，就通过回调写入进度队列，主线程消费队列转成SSE事件推给前端。前端看到的是实时进度条，不是一直在转圈等结果。"

### Q5：工具层为什么要做热插拔？

> "以后要接第三方工具体系（MCP协议）。所有工具统一继承BaseTool接口，注册后LangGraph Harness编排时自动发现可用工具。新增一个工具不需要改Agent代码。"

## 五、面试时的讲述节奏

**第一步：画图（30秒）**

在白板上或口头画那个 Plan → Orchestrate → Verify 的闭环图。画图比说话有力10倍。

**第二步：讲流程（1分钟）**

用第三节那张表，每个Agent一句话。说完问面试官："需要我展开讲某个环节吗？"

**第三步：亮设计决策（1分钟）**

挑2-3个你最骄傲的设计决策主动讲：
- "我最有意思的设计是XXX"（比如计划驱动的并行编排）
- "我踩过的坑是XXX"（比如LLM输出不稳定导致步骤解析失败，加了JSON Schema约束解决）

**第四步：反问（30秒）**

"你们现在Agent这块有什么具体场景在探索吗？"
——把球踢回去，让他变成主动方。同时也判断他到底懂不懂。

## 六、如果面试官完全不懂LangGraph怎么办

这种情况常见。他的问题可能是泛泛的"你用什么框架"、"怎么保证质量"。

**策略：降维解释，不谈术语。**

> "我用了一个叫LangGraph的编排框架。你可以理解为一个自动化的测试流水线：系统自动拆需求、自动调度多个AI去做不同的事、做完了自动检查。如果哪里不对，自动回去重做。"

用"流水线"、"自动拆需求"、"自动检查"代替 StateGraph、Conditional Edge 等术语。他懂了概念就够，不需要纠正他的用词。

## 七、你不是在"背答案"

面试不是考试。这份指南是用来帮你**梳理自己的思路**的——项目是你做的，你本来就懂，只是不知道怎么讲。

对着指南练一遍：闭上眼睛，想象自己在给同事讲这个项目是怎么设计的。能不看文档完整讲出来，就够了。
