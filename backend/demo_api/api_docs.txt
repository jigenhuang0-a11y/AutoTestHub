## Demo API — 商品管理接口文档

以下接口全部部署在测试平台上，可用于 API 自动化测试。

### 基础信息

- 基础路径: http://localhost:8000/api/demo
- 认证方式: 无需认证（Demo 模块）
- 数据格式: JSON

---

### 1. 商品列表

- **接口**: GET /api/demo/products/
- **描述**: 获取所有商品列表，支持分类和状态筛选
- **查询参数**:
  - category (string, 可选): 按分类筛选，不区分大小写
  - is_active (boolean, 可选): 按上架状态筛选，值为 true 或 false
- **成功响应**: 200 — 商品对象数组
- **响应示例**:
```json
[
  {
    "id": 1,
    "name": "测试商品A",
    "description": "这是一个测试商品",
    "price": "99.99",
    "stock": 100,
    "category": "电子产品",
    "is_active": true,
    "created_at": "2024-01-15T10:30:00Z",
    "updated_at": "2024-01-15T10:30:00Z"
  }
]
```
- **测试用例建议**:
  - 正向: 不传参数获取全部商品 → 期望200 + 数组
  - 筛选: ?category=电子产品 → 期望200 + 只返回该分类
  - 筛选: ?is_active=false → 期望200 + 只返回下架商品
  - 组合: ?category=电子产品&is_active=true → 期望200
  - 边界: 不存在的分类 → 期望200 + 空数组

---

### 2. 创建商品

- **接口**: POST /api/demo/products/
- **描述**: 创建一个新商品
- **请求头**: Content-Type: application/json
- **请求体 (JSON)**:
  - name (string, 必填): 商品名称
  - price (number, 必填): 价格，不能为负数
  - description (string, 可选): 商品描述
  - stock (integer, 可选): 库存数量，不能为负数，默认0
  - category (string, 可选): 商品分类
  - is_active (boolean, 可选): 是否上架，默认true
- **成功响应**: 201 — 创建的商品对象
- **错误响应**: 400 — 参数校验失败
- **请求示例**:
```json
{
  "name": "新商品",
  "price": 199.99,
  "stock": 50,
  "category": "电子产品",
  "description": "新上架的商品"
}
```
- **测试用例建议**:
  - 正向: 完整参数创建 → 期望201 + 返回完整对象含id
  - 正向: 最小参数（仅name+price） → 期望201
  - 异常: name为空字符串 → 期望400 + error信息
  - 异常: price为负数 → 期望400
  - 异常: stock为负数 → 期望400
  - 异常: 缺少name字段 → 期望400
  - 边界: price=0 → 期望201（0元商品合法）
  - 边界: stock=0 → 期望201

---

### 3. 商品详情

- **接口**: GET /api/demo/products/{id}/
- **描述**: 获取指定商品的详细信息
- **路径参数**: id (integer, 必填): 商品ID
- **成功响应**: 200 — 单个商品对象
- **错误响应**: 404 — 商品不存在
- **测试用例建议**:
  - 正向: 传入存在的ID → 期望200 + 完整对象
  - 异常: 传入不存在的ID → 期望404
  - 异常: 传入非数字ID（如"abc"） → 期望404

---

### 4. 更新商品（全量）

- **接口**: PUT /api/demo/products/{id}/
- **描述**: 全量更新指定商品的所有字段
- **路径参数**: id (integer, 必填): 商品ID
- **请求头**: Content-Type: application/json
- **请求体**: 同创建接口
- **成功响应**: 200 — 更新后的商品对象
- **错误响应**: 400/404
- **测试用例建议**:
  - 正向: 更新所有字段 → 期望200
  - 异常: 更新不存在的商品 → 期望404
  - 异常: price为负数 → 期望400

---

### 5. 部分更新商品

- **接口**: PATCH /api/demo/products/{id}/
- **描述**: 部分更新指定商品的字段
- **路径参数**: id (integer, 必填): 商品ID
- **请求头**: Content-Type: application/json
- **请求体**: 只传需要更新的字段
- **成功响应**: 200 — 更新后的商品对象
- **测试用例建议**:
  - 正向: 只更新price → 期望200 + 只price变化
  - 正向: 只更新stock → 期望200
  - 异常: 更新不存在的商品 → 期望404

---

### 6. 删除商品

- **接口**: DELETE /api/demo/products/{id}/
- **描述**: 删除指定商品
- **路径参数**: id (integer, 必填): 商品ID
- **成功响应**: 204 — 无响应体
- **错误响应**: 404 — 商品不存在
- **测试用例建议**:
  - 正向: 删除存在的商品 → 期望204
  - 异常: 删除不存在的商品 → 期望404
  - 幂等: 重复删除同一商品 → 期望404

---

### 7. 商品分类列表

- **接口**: GET /api/demo/products/categories/
- **描述**: 获取所有已上架商品的分类列表（去重）
- **成功响应**: 200 — 分类字符串数组
- **响应示例**: ["电子产品", "服装", "食品"]
- **测试用例建议**:
  - 正向: 获取分类 → 期望200 + 数组

---

### 8. 商品统计

- **接口**: GET /api/demo/products/stats/
- **描述**: 获取商品统计信息
- **成功响应**: 200
- **响应示例**:
```json
{
  "total_products": 100,
  "active_products": 85,
  "total_stock": 5000,
  "avg_price": 89.99
}
```
- **测试用例建议**:
  - 正向: 获取统计 → 期望200 + 包含所有字段
